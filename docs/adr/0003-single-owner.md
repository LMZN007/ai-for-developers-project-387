# В сервисе один владелец

Регистрация в сценарий не входит (см. README), поэтому второго владельца невозможно завести через интерфейс. Решили, что владелец ровно один и все типы встреч, доступность и записи принадлежат ему. Мы отклоняемся от Cal.com, где у каждого пользователя своя страница `cal.com/<user>`. Зато не нужны идентификатор владельца в данных и в адресах и выбор владельца на страницах гостя.

## Considered Options

- **Несколько владельцев из начальных данных (seed)** — отвергнут: усложняет модель данных и адреса ради владельцев, которых никто не может создать.

## Consequences

- Если регистрация появится, придётся добавить владельца в модель данных, в контракт API и в адреса публичных страниц.
