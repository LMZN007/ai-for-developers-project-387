# Contract-first: API описывается в TypeSpec

API сервиса описан один раз в `packages/contract/main.tsp`; из него генерируются OpenAPI 3.1 и типизированный SDK, по которым работают и бекенд, и фронтенд. Так сервер и клиент не расходятся: изменение API начинается с контракта и `mise run gen`, а не с кода обработчика. TypeSpec выбран вместо ручного OpenAPI YAML, потому что он короче и проверяется компилятором.

## Considered Options

- **Code-first** (схемы в коде сервера, OpenAPI выводится из них) — отвергнут: контракт оказывается привязан к фреймворку бекенда, а фронтенд зависит от сборки сервера.
- **OpenAPI YAML вручную** — отвергнут: многословно, ошибки видны только при генерации.

## Consequences

- `packages/contract/generated/` не редактируется и не коммитится.
- Веб-клиент ходит в API только через сгенерированный SDK.
